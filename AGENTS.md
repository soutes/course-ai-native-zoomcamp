`weekly` is a Django app that reads GitHub history and produces a Monday-morning
retrospective over a project portfolio. See [SPEC.md](SPEC.md) for why, [backlog.md](backlog.md) for what is next.

Documents

- `docs/process.md` - how work is organized

Commands

- `uv sync` - install dependencies
- `uv run manage.py runserver` - dev server at http://127.0.0.1:8000/
- `uv run manage.py triage` - portfolio curation plan, dry run, changes nothing
- `uv run manage.py triage --apply` - the only command that writes to GitHub
- `uv run manage.py migrate` - apply migrations
- `uv run manage.py makemigrations portfolio` - after changing models
- `uv run pytest` - the whole suite
- `uv run pytest tests/test_triage.py` - one test file
- `uv run ruff check .` and `uv run ruff format .` - run both before committing
- `uv run manage.py check` - Django system check

Rules

Layering

- `portfolio/services/` imports **no Django and no LLM**. It holds rules, not delivery.
- Delivery surfaces - management commands, views, templates - do the wiring. Keep them thin.
- `github.py` is the only module that touches the network. Nothing else makes HTTP calls.
- This layering is why the app moved from a Typer CLI to Django by rewriting one file. Do not
  erode it for convenience.

Determinism

- Momentum stats, health checks and triage classification are **deterministic**. Never call an LLM from them. That is what makes `--no-llm` trivially correct.
- `render` must work with `coaching = None`. Always.
- One batched LLM call per report, never one per repo - only a batched prompt sees
  portfolio-wide patterns.
- Send commit subjects and diffstat numbers to the LLM. **Never full diffs.**
- LLM advice is about **behavior**, not code. "You opened a third project before finishing the first", never "refactor the parser".

Writes to GitHub

- The tool **never deletes a repository** and **never archives one**. Archiving does not hide a repo, so it solves nothing here.
- The single write this app performs is `PATCH /repos/{owner}/{repo}` with `private: true`.
- `triage` is dry-run by default. `--apply` must warn and prompt before touching anything.

Config and secrets

- Configuration comes from the environment only. No secrets in code, no secrets in committed
  files.
- `SECRET_KEY` has no fallback when `DEBUG` is off - the app must refuse to start.
- Never commit `.env`, `db.sqlite3`, `.cache/`, or `staticfiles/`.

Conventions

- ISO week is Monday 00:00 to Sunday 23:59, local time. Everywhere.
- Escape text before printing it with Rich. TOML keys like `[me]` and repo descriptions are
  eaten as markup otherwise - this has bitten twice.
- Tests run off fixtures and never hit the network.
- Do not hand-edit `portfolio/migrations/` - it is generated by `makemigrations`.
- Do not add dependencies without asking.

Working

- Work [backlog.md](backlog.md) in order, one task per commit. Issue numbers match task
  numbers: task 14 is issue #14.
- Update the task checkbox in `backlog.md` and close the issue in the same change.
- Only mark a task done when it was **verified running**, not when the code was written.
- This project follows the [DataTalks AI Dev Tools](https://courses.datatalks.club/ai-dev-tools-2026/)
  course pace. Do not jump ahead of the module being taught, even when a later phase is
  technically easy.
- Commit regularly.
